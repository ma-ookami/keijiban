# ケージバン 公開手順(GitHub Pages + Firebase)

家族や友達がリンクを開いて名前を入れるだけで使えるように、ケージバンを公開する手順です。
所要時間は20〜30分くらいです。費用はかかりません(どちらも無料枠で使えます)。
ますせんとは別の Firebase プロジェクトを作ります(データもルールも完全に分かれます)。

## このフォルダのファイル

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体(画面の骨組み。下の css・js を読み込む) |
| `css/style.css` | 見た目 |
| `js/base.js` | 定数・状態・日付・書き込みの土台 |
| `js/data.js` | リアルタイム更新・参加ボード・既読・アイコン |
| `js/render.js` | 画面の描画 |
| `js/events.js` | 画面遷移・ボタン・書き込み・設定などの操作 |
| `js/boot.js` | Firebase との接続・新しい版の確認・テーマ・起動 |
| `firebase-config.js` | Firebase の設定(手順4で貼り付ける)と App Check のキー |
| `firestore.rules` | データを守るルール(手順3で貼り付ける) |
| `manifest.webmanifest` | ホーム画面に追加したときのアプリ名・色の設定 |
| `icon-192.png` / `icon-512.png` / `apple-touch-icon.png` | ホーム画面のアイコン |
| `images/` | 確認用の画像(Git にも公開サイトにも入らない) |
| `README.md` / `OVERVIEW.md` | この手順書 / アプリの概要 |

GitHub にアップロードが必要なのは、`index.html`・`css` フォルダ・`js` フォルダ・`firebase-config.js`・`manifest.webmanifest`・アイコン3つです。`firestore.rules` は Firebase の画面に貼り付けて使います。

---

## 1. Firebase のプロジェクトを作る

1. https://console.firebase.google.com を開き、Google アカウントでログインする
2. 「プロジェクトを作成」を押す
3. プロジェクト名に `keijiban` などを入れて進む
4. Google アナリティクスは使わないので「オフ」にして、作成する

## 2. 匿名ログインをオンにする

ログイン操作をしなくても、ブラウザごとに見分けられるようにする設定です。

1. 左のメニューの「構築」→「Authentication」→「始める」
2. 「Sign-in method」(ログイン方法)タブを開く
3. 一覧から「匿名」を選び、「有効にする」をオンにして保存する

## 3. データベースを作ってルールを貼る

1. 左のメニューの「構築」→「Firestore Database」→「データベースを作成」
2. ロケーションは `asia-northeast1 (Tokyo)` を選ぶ(あとから変えられません)
3. 「本番環境モードで開始」を選んで作成する
4. 作成できたら「ルール」タブを開く
5. 最初から入っている文字をすべて消し、このフォルダの `firestore.rules` の中身をすべてコピーして貼り付ける
6. 「公開」を押す

## 4. 設定をコピーする

1. 左上の歯車マーク →「プロジェクトの設定」
2. 下のほうの「マイアプリ」で、ウェブのマーク `</>` を押す
3. アプリのニックネームに `keijiban` などを入れて「アプリを登録」(「Firebase Hosting も設定する」のチェックは不要)
4. 表示されたコードのうち、`const firebaseConfig = { ... };` の `{ }` の中身をコピーする
5. このフォルダの `firebase-config.js` を開き、`window.FIREBASE_CONFIG = { };` の `{ }` の中に貼り付けて保存する

> この値は公開されても問題ありません。データは手順3のルールで守られています。

## 5. GitHub で公開する

1. https://github.com で右上の「+」→「New repository」
2. Repository name に `keijiban` と入れ、**Public** を選んで「Create repository」
3. 「uploading an existing file」から、上の「アップロードが必要なファイル」をドラッグして置き、「Commit changes」
4. リポジトリの「Settings」→ 左の「Pages」→「Branch」で `main` と `/ (root)` を選び「Save」
5. 1〜2分待つと公開URLが出ます:`https://(あなたのユーザー名).github.io/keijiban/`

(VS Code から使うときは、このフォルダで `git init` してから GitHub に公開してください。)

## 6. 公開URLを Firebase に登録する

1. Firebase の「Authentication」→「設定」タブ →「承認済みドメイン」
2. 「ドメインの追加」で `(あなたのユーザー名).github.io` を追加する(ますせんで追加済みでも、新しいプロジェクトなのでもう一度必要です)

## 7. 動作確認

1. 公開URLを開き、ボードを作る
2. 右上の 🔗 で招待リンクをコピーする
3. スマホや、パソコンのシークレットウィンドウでそのリンクを開き、別の名前で参加する
4. 片方で「📦 荷物届いた」を押すと、もう片方にすぐ出て、押した側に「◯◯が見た」と出れば完成です

## うまくいかないとき

| 表示 | よくある原因 |
|---|---|
| 「Firebaseの設定が読み込めませんでした」 | `firebase-config.js` を貼り付けていない、またはアップロードし忘れている |
| 「サーバーにつながりませんでした」 | 手順2の「匿名」がオンになっていない |
| 「データを読み込めませんでした」 | 手順3のデータベース作成、またはルールの「公開」がまだ |
| 「保存できませんでした」 | ルールの貼り付けが途中で切れている。`firestore.rules` を丸ごと貼り直す |
| ページが404になる | Pages 設定後、数分待っていない。URLの最後の `/keijiban/` を確認 |

## App Check を設定する(任意・無料枠を荒らされないように)

ますせんの README の「App Check を設定する」と同じ手順です。キーはケージバンのプロジェクトで新しく作り、
`firebase-config.js` の `window.APPCHECK_SITE_KEY = "";` に貼ってからアップロードしてください。
**アップロードして1日ほど使ってから「適用」を押してください。** 先に適用するとアプリが動かなくなります。

## ホーム画面に追加する

- **iPhone(Safari)**:ボードを開いて、共有ボタン(□に↑)→「ホーム画面に追加」
- **Android(Chrome)**:右上の「︙」→「ホーム画面に追加」
- iPhone のホーム画面アプリは Safari とは別扱いです。最初の1回だけ参加画面が出るので、「前に参加したことがある人」から自分の名前を選んでください。2回目からは最後に開いたボードが自動で開きます。

## アプリを更新するとき

1. 手元で確認する:このフォルダで `npx http-server -p 8080 -c-1` を動かし、http://localhost:8080 を開く
2. 変更したファイルを GitHub にアップロード(またはコミットして同期)する。1〜2分で反映されます
3. `firestore.rules` を変えたときは、Firebase の「Firestore Database」→「ルール」に貼り直して「公開」も必要です

## 知っておくこと

- **リンクを知っている人は誰でも参加できます。** リンクは家族や仲間の中だけで共有してください。
- **別のスマホやブラウザ(LINEの中のブラウザなど)で開くと、参加画面が出ます。** 「前に参加したことがある人」から自分の名前をタップすれば、同じ人として続けられます。名前を入れ直すと別の人として増えてしまいます。
- **合言葉(数字4桁)**:ボードを作る人は必須、ほかのメンバーは任意です。なりすましを防ぎます。
- **「見た」の仕組み**:ボードを開いた時刻を記録し、それより前の書き込みを「見た」にします。開いたけれど読んでいない場合も「見た」になります。
- **通知はありません。** 見てほしいことはボードを開いたときに「NEW」と「前回から◯件」で分かります。急ぎの連絡は LINE などで。
- **ボードを作れるのは、1つのブラウザで3つまでです。**
- **名前は本名ではなくニックネームがおすすめです**(10文字まで)。
